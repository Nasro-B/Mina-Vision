### 16 juillet 2026 — BUG MAJEUR : preload sandboxé cassé, cause racine de « presque rien ne marche »

Nasro a signalé, après les vagues précédentes : « presque rien ne marche, ça s'initialise pas, ça fait rien, teste absolument tout. » Diagnostic méthodique par élimination, pas de supposition à aucune étape :

1. `keyring.initialize()` (argon2 + safeStorage + écriture fichier) testé en isolation complète dans un profil Electron dédié → **fonctionne parfaitement**.
2. ABI SQLite Electron 43 vérifié (148) contre le binding natif en cache → **présent et correct**.
3. Console réelle du renderer capturée via un hook temporaire (`webContents.on('console-message')`) → révèle l'erreur exacte : `Unable to load preload script... Error: module not found: ./preload-api.cjs`, suivie de `Uncaught TypeError: Cannot read properties of undefined (reading 'onCameraFrame')` à `renderer.js:581`.

Root cause confirmée par la documentation officielle Electron (recherche réelle) : depuis Electron 20, un preload avec `sandbox: true` (durcissement de sécurité voulu, pas à affaiblir) tourne avec un `require()` polyfillé qui **ne résout pas les modules CommonJS locaux** — `preload.cjs` faisait `require('./preload-api.cjs')`, ce qui échouait systématiquement. Conséquence : `window.mina` restait `undefined`, provoquant un crash synchrone dès la première utilisation dans `renderer.js`, qui coupait l'exécution du script AVANT que la quasi-totalité des `addEventListener` (tous les boutons : Initialiser, Détecter le Huawei, etc.) ne soient jamais enregistrés. Un seul bug racine expliquant un symptôme large sur toute l'interface.

**Fix** : fusion de `preload-api.cjs` dans `preload.cjs` (fichier CommonJS unique, sans `require` cross-fichier), `createPreloadApi` toujours exportée pour `tests/preload-api.test.mjs`, `contextBridge.exposeInMainWorld` gardé derrière un check `typeof === 'function'` pour rester no-op hors Electron réel (vérifié : `require('electron')` hors Electron renvoie un chemin, jamais une exception). `preload-api.cjs` supprimé. `tests/ui-security-contract.test.mjs` mis à jour vers le fichier fusionné.

**Vérifié de bout en bout, pas juste par les tests unitaires** : console renderer propre après fix, `npm run smoke` → exit 0, et Nasro a cliqué « Initialiser » pour de vrai dans l'appli relancée et a reçu sa vraie phrase de récupération — preuve la plus forte possible. Gate final : `npm test` → 214 fichiers/1562 tests verts, zéro régression.

### 16 juillet 2026 — compaction automatique de la mémoire de travail (demande explicite Nasro, hors plans structurés)

Nasro a demandé une amélioration de la mémoire/contexte « comme moi » (Claude Code) : compaction automatique pour continuer indéfiniment sur une tâche longue, la mémoire de travail de Mina Vision étant bornée sans mécanisme équivalent.

**Investigation d'abord** (pas de supposition) : deux structures bornées en FIFO existaient, jetant silencieusement les entrées les plus anciennes sans jamais les résumer :
1. `src/memory/short-term.mjs` (`entries.shift()` une fois `maxEvents`/`maxTokens` dépassés). Vérifié par grep : `memoryService.shortTerm.list()` n'a **aucun appelant réel** nulle part dans `src/` — seul `.add()` est utilisé (depuis `remember()`). Corriger l'éviction de cette structure n'aurait eu aucun effet observable — **délibérément laissé tel quel**, conforme à la règle « pas de conception pour du hypothétique ».
2. `selectedResearch` dans `src/memory/runtime-controller.mjs` (`.slice(-MAX_RESEARCH_EVIDENCE)`, cap 50) — celle-ci **est** réellement consommée : alimente `missionEvidence()` → câblé à `evidenceProvider` dans `main.mjs:718` → consommé par `createMinaRuntime` (`src/core/mina-runtime.mjs`) pour CHAQUE mission. C'est la vraie cible : sur une mission de recherche longue (nombreux appels `readFile`/`readWeb`), les preuves les plus anciennes disparaissaient silencieusement du contexte de travail une fois 50 éléments dépassés — exactement la même catégorie de perte que la compaction de Claude Code est censée éviter.

`src/memory/consolidator.mjs` (primitive de résumé déjà construite et testée au plan v2 mémoire/recherche) n'était **jamais appelée nulle part** dans `src/` — vérifié par grep, zéro résultat hors son propre fichier. Réutilisée plutôt que dupliquée.

**Construit** : `src/memory/research-evidence-compactor.mjs` (`createResearchEvidenceCompactor`). Conserve toujours les `maxItems - 1` éléments bruts les plus récents ; au dépassement, replie systématiquement (résumé existant s'il y en a un + tout le surplus) en **un seul** résumé frais via `consolidator.consolidate()` — le résumé ne grossit jamais d'un round à l'autre, `list().length` reste `<= maxItems` indéfiniment (propriété testée sur 20 rounds simulant une tâche longue). Résumé taggé `method: 'model_inference'` (valeur réelle de l'enum zod de `src/grounding/evidence-validator.mjs`, jamais une valeur inventée) — classement honnête : un claim reposant uniquement sur une preuve compactée est correctement rétrogradé `inference`/`uncertain` par `rankSource()` (`source-policy.mjs`), jamais faussement `verified`. `sourceEventIds` d'origine tracés via le champ optionnel `result` du schéma (pas de champ ajouté hors schéma — `evidenceSchema` est un `strictObject`, tout champ en trop aurait fait échouer la validation). `summarize` injecté (défaut déterministe sans dépendance LLM, remplaçable plus tard).

**Bug de conception trouvé et corrigé avant tout code produit** : premier calcul de `overflow` laissait la liste finale à `maxItems + 1` (oubliait que le résumé lui-même occupe un slot) — corrigé (`keepCount = maxItems - 1`), prouvé par test réel avant la version finale.

**Branché** dans `src/memory/runtime-controller.mjs` (`read()`, `missionEvidence()`, `status()`, `lock()`) à la place de `selectedResearch`/`.slice()` — extension non-cassante (nouveau paramètre optionnel `researchEvidenceCompactor` avec valeur par défaut). 8 nouveaux tests dont un test croisé réel contre le vrai `evidenceSchema` (`createEvidenceValidator` importé directement, pas un mock du schéma).

**Gate exécuté et vert** : `npm test` (213 fichiers/1556 tests, contre 212/1548 avant) + `npm run test:integration` (13/13, 34/34 tests). Aucune régression.

**Trouvé en cours de route, hors scope de cette tâche, flagué séparément (spawn_task, pas corrigé ici)** : `createEvidenceValidator` (`src/grounding/evidence-validator.mjs`) n'est instancié nulle part dans `src/` — le validateur anti-hallucination existe et est testé mais n'est jamais réellement appelé sur les preuves produites par `mina-runtime.mjs`. En plus, `memoryEvidence()` (même fichier que `runtime-controller.mjs`) tague ses preuves `method: 'memory_recall'`, valeur absente de l'enum zod — échouerait la validation même une fois branché. Tâche flaguée à part (`task_7e3ae118`) pour ne pas mélanger avec la compaction.
